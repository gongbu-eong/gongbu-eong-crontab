# 커뮤니티 가상 계정의 설정 유지 및 중복 방지

## 개선 방향

인물 설정을 매번 새로 만드는 대신 `users.id`별 고정 프로필을 기준으로 생성한다.
현재도 `persona`는 저장되지만 나이대·배경·말투의 자유 서술만 있어 취업 여부나
현재 직무와 준비 직렬이 혼동될 수 있었다. 기존 기획은 작성자를 정하기 전에
만들었고, 과거 기록도 주로 전체 최근 제목에 의존했다.

이제 **고정 신원 → 작성자별 기획 → 이력 기반 글/댓글 생성 → 별도 검수 → 저장** 순서다.
기존 `GPT_API_KEY`, `OPENAI_MODEL`을 사용하며 모델을 바꾸지 않는다.
생성 및 검수는 AI로 수행하고, 설정 보관·작성자 자격·글자 수·중복 해시 검사는 코드와 DB가 담당한다.

## 고정 설정

일반 회원의 실제 개인정보 컬럼은 변경하지 않는다. `users.id`를 FK로 갖는
`community_seed_personas`에 운영용 가상 설정을 보관한다.
작성 대상은 계속 `status='active'`이고 이메일이 `@example.local`로 끝나는 계정뿐이다.

추가 컬럼:

| 컬럼 | 용도 |
| --- | --- |
| `canonical_identity` | 출생연도, 취업 상태, 현재 직무, 준비 직렬, 준비 단계 |
| `identity_status` | `uninitialized`, `active`, `needs_review` |
| `identity_version` | 운영자가 설정을 변경했는지 확인하는 버전 |
| `identity_locked_at` | 고정 설정 확정 시각 |
| `identity_review_notes` | 과거 기록에서 발견된 설정 충돌 |

예시:

```json
{
  "birthYear": 2000,
  "employmentStatus": "unemployed",
  "currentRole": "취업 준비생",
  "targetRole": "행정직",
  "preparationStage": "필기시험 준비"
}
```

`birthYear`는 고정되고 연도 기준 나이는 코드에서 계산한다. 오늘 26세였다가
내일 임의로 30세가 되지 않도록 생성과 검수에 같은 기준을 준다. 생일 정보가
없으므로 정확한 만 나이를 단정하지 않도록 한다. 취업/합격/직렬 변경은 자동으로
추가하지 않는다. 말투와 기존 배경은 원래 `persona`를 계속 사용한다.

처음 작성자로 선택된 시점에 고정 설정을 초기화한다. 사용하지 않는 모든 계정에
한꺼번에 유료 AI 요청을 보내지는 않는다. 초기화 때도 기존 수동 작성 글과 댓글을
참고하며, 이미 충돌하는 기록이 발견되면 `needs_review`로 보관하고 발행을 중단한다.
이 계정은 이후 새 실행의 작성자 후보에서도 제외한다. 이미 진행 중인 실행에
포함되어 있으면 운영자 확인 전에는 그 실행을 재개하지 않는다.

## 작성 기억과 중복 검사

`community_seed_memories`에 글별 작성자, 주제 키, 주제/본문 해시, 사건 요약,
검수 결과, 원본 글 ID, 예약 공개 시각을 함께 저장한다.
본문과 제목의 단순 반복뿐 아니라 같은 질문이나 경험을 표현만 바꾸어 다시
올리는 경우도 검수한다. 같은 분야라는 이유만으로 무조건 중복 처리하지는 않는다.
후속 글은 구체적인 새 정보가 있어야 하며, 허가되지 않은 신원 변화는 허용하지 않는다.

검사 범위:

- 작성자별 최근 글 12개, 댓글·대댓글 12개, 저장된 작성 기억 60개를 참고한다.
- 과거 수동 작성 글과 미래 예약 글도 포함한다. AI에 전달하는 글 본문은 건당
  앞 1,200자, 기억 요약은 앞 240자로 제한한다. 저장된 원문을 자르지는 않는다.
- 같은 날 아직 저장하지 않은 앞선 초안도 작성자별 참고 자료로 전달한다.
- 제목/본문이 동일하거나 최근 원문과 거의 같으면 코드에서 먼저 거부한다.
- 모든 과거 글의 동일 제목/본문과 모든 저장 기억의 동일 주제/본문 해시는
  DB에서 다시 검사한다. 주제 및 본문 해시는 작성자별 UNIQUE로 보호한다.
- 별도 AI 검수 요청으로 글 작성자뿐 아니라 댓글/대댓글 발언자 전원의 설정을 확인한다.
- 검수에서 거절된 결과를 승인으로 바꾸도록 요청하지 않는다. 문제 조건을 전달해
  글 자체를 다시 생성하며, 최대 3개 후보까지 통과하지 못하면 실패 처리한다.

AI 의미 판단은 완벽하지 않다. 오래된 글의 모든 문장을 매번 AI에 보내는 것도
아니므로 모든 유사 글과 사실 충돌을 100% 탐지한다고 보장하지 않는다.
고정 프로필, 작성 기억, 기계적 중복 검사, AI 검수를 함께 쓰는 방어 구조다.
새 요약 기억은 이 변경 이후부터 쌓이며 과거 글 전체를 자동 요약하는 유료
백필은 실행하지 않는다.

## 실행 및 실패 복구

1. 계정 자격과 기존 설정을 확인하고 고정 설정이 없으면 한 번만 초기화한다.
2. 고정 프로필과 작성 이력을 입력으로 작성자까지 지정한 하루 기획을 만든다.
3. 글과 댓글/대댓글을 생성하고 발언자별 설정 및 작성자 중복을 검수한다.
4. 통과한 초안과 검수 결과를 `community_seed_runs.drafts`에 체크포인트로 저장한다.
5. 모든 초안이 준비되면 작성자와 프로필을 다시 확인하고 행 잠금을 잡는다.
6. 글·댓글·기억·완료 상태를 같은 트랜잭션으로 저장한다. 중간 실패 시 함께 롤백한다.

같은 날짜 재시도는 저장된 초안을 재사용하지만 최신 이력을 기준으로 다시 검수한다.
이때 기존 초안이 충돌하면 무조건 발행하지 않고 `review_saved_draft` 단계에서 중단한다.
설정 버전이나 내용이 생성 도중 바뀌어도 중단한다. 운영자가 설정을 수정할 때는
해당 계정의 공개 기록과 미완료 실행을 함께 확인해야 한다.

구버전에서 완료된 실행과 공개 글은 그대로 둔다. 구버전 미완료 실행은
`legacy_snapshot`에 원래 actors/plan/drafts를 백업하고 새 기획과 검수로 재생성한다.
추가 AI 비용이 발생할 수 있으며 기존 체크포인트를 무단 삭제하지 않는다.
재실행 날짜가 바뀌면 기존처럼 새 날짜의 실행이며 과거 날짜로 소급 발행하지 않는다.

## 배포 순서

1. 기존 커뮤니티 크론 작업을 멈추고 실행 중인 작업이 끝났는지 확인한다.
2. 같은 서비스 DB에 [추가 SQL](database/20260928_community_identity_memory.sql)을 실행한다.
   기존 `20260923_community_daily_seed.sql`이 먼저 적용되어 있어야 한다.
   신규 인덱스는 일반 CREATE INDEX이므로 운영 데이터가 크면 점검 시간에 적용한다.
3. 새 크론 소스를 배포하고 프로세스를 재시작한다. 프런트/백엔드 컬럼 변경은 없다.
4. 필요하면 `npm run seed:community` 또는 기존 수동 실행 API로 실행한다.

자동 실행은 계속 한국시간 00:01, 글 수는 하루 3~20개다. 검수 요청이 추가되어
기존보다 AI 호출량과 시간이 증가한다. 정상 신규 실행은 기존 생성 요청에
글마다 검수 1회, 최초 고정 설정 초기화 시 1회가 추가된다. 내용 재생성이나
네트워크 재시도 시 더 증가한다. 실제 비용과 운영 DB 쓰기가 발생한다.

SQL은 테이블/컬럼/인덱스만 추가하며 운영 DB에 자동 실행하지 않는다.
내부 프로필과 작성 기억 테이블은 RLS로 보호하고 서버 소유자/BYPASSRLS 연결을 쓴다.
가상/AI 운영 콘텐츠라는 표시는 별도로 유지해야 하며 실제 회원 경험담으로 위장하는
용도로 사용하지 않는다. 이번 변경은 공개 화면 표시를 변경하지 않는다.

## 운영 확인

```sql
SELECT u.id, u.email, p.identity_status, p.identity_version,
       p.canonical_identity, p.identity_review_notes, p.identity_locked_at
FROM public.users u
LEFT JOIN public.community_seed_personas p ON p.user_id = u.id
WHERE u.email::text ILIKE '%@example.local'
ORDER BY p.identity_status, u.id;

SELECT seed_date, status, continuity_version,
       jsonb_array_length(drafts) AS ready_drafts, error_message,
       legacy_snapshot IS NOT NULL AS has_legacy_backup
FROM public.community_seed_runs ORDER BY seed_date DESC LIMIT 10;

SELECT user_id, post_id, topic_key, summary, published_at
FROM public.community_seed_memories ORDER BY published_at DESC LIMIT 30;
```

`needs_review`의 사유를 확인하고 실제 과거 기록과 모순되지 않는 고정 설정을
운영자가 결정한다. 값 수정 시 `identity_version`도 증가시킨다. 이미 저장된
미완료 실행의 스냅샷과 달라지면 자동 재개하지 않는다. 메모리/프로필/초안을
삭제해서 검사를 우회하지 않는다. 관리 UI는 이번 변경에 포함되지 않는다.

## 검증

`npm test`, `npm run typecheck`로 검증한다. 모의 AI와 메모리 PostgreSQL을 사용하며
유료 AI나 운영 DB를 호출하지 않는다. 프로필 재사용, 날짜 변경, 글/댓글 검수,
거절 후 재생성, 중복 차단, 마이그레이션 재실행, 구버전 백업, 롤백과 재개를 검증한다.
